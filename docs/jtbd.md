# Jobs to be done

## The member

**When** money leaves my account for things I've forgotten, **I want** someone to stop the ones I don't use without touching the ones my family relies on, **so I can** save money without becoming the household's admin department.

- Ask me only when it matters, one question at a time, and make the answer a tap.
- If I said keep it, leave it, unless the price goes up.
- If I'm on Manual, nothing happens without my yes.
- If I cancelled something and it charges me again, tell me and get it back.

What Handover gives them: the WhatsApp pane, where every decision becomes at most one message, with up to three reply buttons.

## The ops team

**When** a decision is escalated or a member complains, **I want** to see exactly what the system saw and why it did what it did, **so I can** fix the member's problem fast and know whether it will happen again.

- Which charges and which chat message made a rule fire.
- Whether the model or a rule made the call, and which rule.
- What was attached: a refund request, an urgent deadline, the parent bill to cancel through.

What Handover gives them: the decision trace. Hover a fired rule to light up the evidence; the handover line says where the model stopped and the rules took over.

## The builder who changes the rules

**When** I change a threshold or add a rule, **I want** to know before shipping whether anything got riskier, **so I can** move fast without trading member trust for a bigger savings number.

- A hard gate: no new false cancels.
- A per-case diff, so I see what moved and why.
- Attribution, so a right answer reached by the wrong rule shows up as a latent bug.

What Handover gives them: rules as config with an on/off toggle per rule, the Evals tab that re-scores in the browser, and `npm run eval -- --compare`, which fails if weighted cost went up.
